# 01_project_overview — 継走（keisou） [v3]

## 1. プロジェクトの目的と背景

**継走（keisou）** は、ローカル環境で併用する自律型AIコーディングエージェント（**Claude Code** / **Codex CLI** / **Gemini CLI** / **Antigravity CLI（`agy`・β対応）**）の5時間ローリング制限（レート制限）および週間クォータ利用状況を**単一のCLIコマンドで横並び可視化**し、さらに長時間自律実行（`ccw` の上位互換リレー実行）において**クォータ上限（100%）に到達する前に先回りしてソフト停止・引き継ぎファイル（`HANDOFF.md`）生成・次エージェントへの自動/選択式バトンタッチ**を行う Go 製シングルバイナリ CLI ツールである。

### 解決する課題

1. **利用状況確認の煩雑さ**: ツールごとに異なるディレクトリ（`~/.claude`, `~/.codex`, `~/.gemini`）やセッション内の独自コマンド（`/usage`, `/stats` 等）を個別に起動・切り替えながら残枠を確認する手間の解消。
2. **100%到達による強制ロックと作業中断**: 実行中にレート制限100%へ到達するとAPIエラーで強制停止し、作業状態の要約や引き継ぎファイルすら書けなくなる問題の回避。
3. **マルチエージェント間のコンテキスト継承リレー**: 90%〜98%の安全しきい値で自律的に作業を切り上げさせ、余力のある別エージェントへ引き継ぎファイルを渡して作業を継続させることで、長時間の無人・半自動開発を完走させる。

## 2. 全体ワークフロー

### 2.1 `keisou status`（横並び利用状況比較モード）

1. 設定ファイル（`--config` フラグ → 環境変数 `KEISOU_CONFIG` → OS標準パス `~/.config/keisou/config.json` または Windows `%APPDATA%\keisou\config.json` の優先順）から対象プロバイダ設定とパース対象パスを読み込む。設定ファイル未作成時はデフォルト設定で動作する。
2. 各プロバイダ（`claude`, `codex`, `gemini`, `antigravity`）のローカルセッションログ・キャッシュ・テレメトリを**並行（非消費型・読み取り専用）**で解析する。
3. 5時間枠使用率（`5h Used %`、ローカル推定時は `(est)` 明示）、推定残り時間（`Reset In`）、週間枠使用率／リセット残り時間（`Weekly`）、アクティブモデル（フォールバック発生有無）を算出し、ターミナルに整形テーブル（または `--json` 出力）で表示する。
4. `--watch` 指定時は `PollIntervalSec`（または `--interval <sec>`）間隔で定期更新する。通常テーブル表示時は画面クリアして再描画し、`--json --watch` 併用時は1更新1行のコンパクト JSON 配列（NDJSON形式）を `stdout` へ出力する。

### 2.2 `keisou run`（しきい値監視・自律バトンタッチ実行モード）

1. **入力検証・排他ロック取得・初期エージェント選定**:
   - タスクプロンプトは位置引数（`keisou run "<prompt>"`）または `--prompt-file <path>` で指定する（両方同時指定は `E_INVALID_ARGS`）。既存 `HANDOFF.md` から引き継いで再開する場合は `--resume` を指定できる（位置引数・`--prompt-file`・`--resume` のいずれも未指定の場合は `E_INVALID_ARGS`）。
   - 作業ディレクトリ配下の `.keisou/run.lock` を排他取得し、二重起動による競合を防止する。
   - `--agent auto`（デフォルト）の場合、有効かつ実行可能（`Available == true`）なツールの現在の実効使用率（`max(5時間枠, 週間枠)`）を取得し、最も使用率が低い（かつ `soft_threshold_pct` 未満の）ツールを初回ランナーとして選択する。
   - `--agent claude|codex|gemini|antigravity` 指定時は、指定ツールを初回ランナーとして優先起動する（すでにしきい値超過の場合は、`--mode auto` なら残余の最適候補へ切替、`--mode ask` なら対話選択、全候補超過ならリセット待機または `--no-wait` で `E_ALL_QUOTA_EXHAUSTED`）。リレー2回目以降は他ツールへの切替を許容する。
2. **監視付きサブプロセス実行**:
   - 選択されたエージェントを非対話モードで起動する。プロンプト文字列は全プロバイダ共通で **`stdin` パイプ経由**で注入する（TTY 競合によるサスペンドおよび Windows `.cmd` 経由の引数破損・コマンドライン長制限を防止）。
   - バックグラウンドのウォッチャー（ポーリング間隔デフォルト 15秒）で対象ツールの5時間枠および週間枠の実効使用率（`max(5h, Weekly)`）を追跡する。
   - 子プロセスが終了コード `0` で自然終了し、出力にレート制限エラーが含まれない場合はタスク完走（`COMPLETED`、終了コード `0`）とみなす。
   - ポーリング間隔の間に子プロセスが非0終了した場合、出力末尾のリングバッファにレート制限シグネチャ（`429` / `rate limit` / `RESOURCE_EXHAUSTED` / `quota exceeded`）が含まれるか、即時再計測した使用率が `soft_threshold_pct` 以上であれば「クォータ／レート制限到達」とみなし、下記の引き継ぎ・リレー手順へ遷移する。それ以外の一般エラー終了は `ABORTED`（`E_INTERNAL`、終了コード `1`）とする。
3. **しきい値到達検知（ソフト停止ライン: デフォルト 95% / ハード上限: 98%）**:
   - **ソフトしきい値到達（`soft_threshold_pct <= used < hard_threshold_pct`）**:
     1. 編集途中ファイル破損を避けるため、まず現行プロセスの自然終了をグレースフル・ドレイン猶予時間（`soft_drain_grace_sec`: デフォルト 15秒）待機する（待機中に子プロセスが終了コード `0` かつレート制限エラーなしで自然終了した場合は `COMPLETED`、待機中にハード上限へ達した場合は即座に打ち切る）。
     2. 未終了であればプロセスツリー全体を安全停止し、`git status --porcelain` / `git diff --stat` で現在の変更状態を捕捉する（Git リポジトリ外の場合は安全にスキップ）。
     3. 残余クォータを使って引き継ぎ専用プロンプト（`HandoffArgs` を使用、タイムアウト 30秒、ファイル編集禁止・要約専念）を1回だけ実行し、標準出力からキャプチャした Markdown を構造検証（`ValidateHandoff`）に通した上で `HANDOFF.md` をアトミックに出力する。途中で 429 / レート制限エラー・タイムアウト・非0終了・品質検証失敗が起きた場合は即座にローカル決定論フォールバックへ降格する。
   - **ハードしきい値到達（`used >= hard_threshold_pct`）または 429 終了時**:
     - APIコールによる引き継ぎ生成を行わず、即座にプロセスツリーを停止した上で、ローカルの元のタスク概要・直近セッションログ末尾・`git status --porcelain`・`git diff --stat` から `keisou` 自身がフォールバック用の `HANDOFF.md` を決定論的に自動生成する。
4. **リレー上限判定と次エージェントへのルーティング（`--mode auto` / `--mode ask`）**:
   - `HANDOFF.md` 保存後、リレー回数が `max_handoff_count` に達している場合は次エージェントを起動せず `HANDOFF.md` を保持したまま `E_MAX_RELAY_EXCEEDED`（終了コード `6`）で安全停止する。
   - `--mode auto`: 残りの候補ツールから最も使用率が低いツールを自動選択し、最新 `HANDOFF.md` を読み込んで作業を継続する初期プロンプトを `stdin` から注入して起動する。
   - `--mode ask`: 子プロセス終了後、フォアグラウンドの親プロセスがターミナルに3ツールの残枠一覧を表示し、対話プロンプト（タイムアウト設定可、タイムアウト時は `auto` 選定へフォールバック）で次の切替先（`[1] codex (21%)`, `[2] gemini (34%)`, `[w] リセット待機`, `[q] 終了`）をユーザーに選択させる。
   - **全ツール枯渇時**: 候補すべてが `soft_threshold_pct` 以上の場合、最もリセット時刻（`ResetAt`）が早いツールの解除時刻＋安全マージン（30秒）までカウントダウン待機したのち自動再開する（`ResetAt` が全候補 `nil` の場合は `max(poll_interval_sec, 60)` 秒待機して再計測。`--no-wait` 指定時は `E_ALL_QUOTA_EXHAUSTED` で終了）。

## 3. MVPスコープと対象外

### MVPスコープ（Phase 1〜3 で実装）

- **対応エージェント**: Claude Code (`claude`), OpenAI Codex CLI (`codex`), Gemini CLI (`gemini`), Antigravity CLI (`antigravity` / `agy`・β対応) の4種。
- **グローバルフラグ**:
  - `--config <path>`（環境変数 `KEISOU_CONFIG` でも指定可）: 設定ファイルパスの明示指定（サブコマンド後置にも対応）。
- **サブコマンドと主要フラグ**:
  - `keisou status`（`--json`, `--watch`, `--interval <sec>`）: 各ツールの5時間枠（推定時は `(est)` 付記）・週間枠・リセット時刻・使用モデルの横並び比較表示。
  - `keisou run`（`--mode auto|ask`, `--agent auto|claude|codex|gemini|antigravity`, `--soft-threshold 95` [エイリアス: `--threshold`], `--hard-threshold 98`, `--handoff HANDOFF.md`, `--prompt-file <path>`, `--resume`, `--no-wait`, `[prompt]`）: 5時間／週間しきい値監視付き実行と引き継ぎバトンタッチ。
  - `keisou handoff`（`--handoff HANDOFF.md`, `--agent claude|codex|gemini|antigravity`, `--task <summary>`）: 現在の git 状態と最新セッションログから API 非消費のローカル決定論生成で手動 `HANDOFF.md` を生成・検証するユーティリティ。
  - `keisou statusline`（`--agent claude|antigravity`, `--quiet`）: Claude Code 等の公式 `statusLine` フックから `stdin` 経由で受け取った `rate_limits` JSON を `keisou-rate-limits.json` へアトミックキャッシュし、`status` / `run` で実測値（`log_exact`）として利用可能にする受け口コマンド。
  - `keisou init`（`--force` 対応）: デフォルト設定ファイル（`config.json`）のアトミック生成と各ツールの CLI / ローカルデータディレクトリ自動検出診断（既存ファイルがあり `--force` 未指定の場合は上書きせず `stderr` へ案内し終了コード `1`）。
- **クロスプラットフォーム**: Windows 11（PowerShell 7 / cmd）および WSL2 / Linux でのシングルバイナリ動作（WSL2からWindows側またはその逆のログパス参照設定にも対応）。

### スコープ外（YAGNI）

- GUI / Webダッシュボードの提供。
- 課金API（従量課金キー）のリアルタイム請求額取得（定額サブスクリプションプランの5時間/週間ローリング制限の可視化・切替に特化）。
- エージェント独自の対話TUIの完全エミュレーション（非対話/ヘッドレス実行ラッパー制御を採用）。

## 4. 非機能要件

- **非消費型高速ステータス取得**: `keisou status` は外部LLM APIを一切呼び出さずローカルファイル解析のみで完結し、実行時間 **200ms 以内** を目標とする。
- **ゼロ依存**: Go 1.23+ 標準ライブラリのみで構築し、外部サードパーティライブラリへの依存をゼロとする。
- **データ保全とアトミックI/O**: `config.json`、`HANDOFF.md`、および `.keisou/handoffs/` アーカイブの書き込みは必ず一時ファイル経由（`Sync()` + `Close()` 後）の `os.Rename` によるアトミック書き込みを行い、中断時のファイル破損を防ぐ。多重起動制御は `.keisou/run.lock` で担保する。
- **クリーンな標準出力分離**: `--json` 指定時やパイプ連携時に標準出力へ進捗ログや警告が混入しないよう、人間向けステータス・ログおよび子プロセスのリアルタイム出力転送はすべて `stderr` へ分離出力する。
